## О проекте

Порт включает исследования, аспекты, узлы ауры, жезлы и посохи, алхимию, инфузию, сети эссенции, големов, снаряжение и Внешние земли. Для расширения содержимого предусмотрены публичный API и отдельный SDK дополнений.

Версия **1.1.0** предназначена для тестирования. Автоматические проверки охватывают правила API и отдельные игровые сценарии. Ручная проверка графики и многопользовательских сценариев продолжается. Хранилище Hidden Magic Box не реализовано.

## Требования

| Компонент | Поддерживаемая версия | Обязательность |
| --- | --- | --- |
| Minecraft | 1.21.1 | Обязательно |
| Java | 21 | Обязательно |
| NeoForge | От 21.1.166 до 21.2, не включая 21.2 | Обязательно |
| Curios | От 9.5.0+1.21.1 до 10, не включая 10 | Обязательно |
| AOP: UI | Совместимая сборка 0.7.x | На клиенте и сервере |

Все зависимости должны быть предназначены для Minecraft 1.21.1 и NeoForge. При отсутствии TerraBlender используется встроенный механизм размещения биомов.

## Установка

1. Установить Minecraft, Java, NeoForge и обязательные зависимости.
2. Поместить `thaumcraft-1.21.1-1.1.0.jar` в каталог `mods` клиента и сервера.
3. Установить совместимый игровой JAR AOP: UI с обеих сторон.

Публичный API включён в игровой JAR. Отдельные API и sources JAR предназначены для разработки и не устанавливаются как моды. Перед проверкой обновлений рекомендуется резервное копирование существующих миров.

### Связанные проекты

- [**Thaumic Tinkerer**](https://github.com/Salossov/AOPTC4-Thaumic-Tinkerer) добавляет устройства, набалдашники и содержимое KAMI. Требуется совместимая сборка ядра.
- [**AOP:TC4 Compact**](https://github.com/Salossov/AOPTC4-Compact) предоставляет необязательную интеграцию рецептов JEI/EMI и подсказки Jade/WTHIT. Эти интеграции отделены от ядра.
- [**AOP: UI**](https://github.com/Salossov/AOP-UI) предоставляет общий интерфейс настроек.

## Настройка и управление

Таумономикон описывает исследования и развитие. Таумометр открывает аспекты при сканировании объектов.

| Клавиша по умолчанию | Действие |
| --- | --- |
| F | Выбор набалдашника |
| H | Переключение подвески |
| G | Изменение режима архитектора |
| Shift+G | Изменение оси архитектора |

Назначения клавиш изменяются в настройках Minecraft.

Клиентская конфигурация находится в `config/thaumcraft-client.toml`, серверная - в каталоге мира. Общее меню настроек открывается через Mods, шестерёнку Таумономикона или кнопку AOP: UI в меню паузы.

Клиентские изменения сохраняются сразу. Серверные изменения применяются кнопкой **«Сохранить»** или клавишей **Esc**. В многопользовательской игре требуется OP 4; владелец одиночного мира может менять настройки без включения читов. Параметры с меткой перезапуска сохраняют действующее значение до перезапуска. Исходные ключи конфигурации и значения по умолчанию сохранены.

## Сборка из исходников

Сначала необходимо собрать AOP: UI и указать её игровой JAR как зависимость Gradle. При установленном JDK 21 из корня этого репозитория выполняется команда:

```powershell
./gradlew.ps1 build -PaopUiJar=C:/dependencies/aopui-1.21.1-0.8.0.jar
```

В Linux и macOS используется `sh ./gradlew` с теми же задачами и параметрами. Зависимости загружаются при первой сборке. Версии Minecraft и NeoForge определены в `gradle.properties`.

| Результат | Назначение |
| --- | --- |
| `mod/build/libs/thaumcraft-1.21.1-1.1.0.jar` | Игровой мод |
| `api/build/libs/thaumcraft-api-1.1.0.jar` | Зависимость для разработки дополнений |
| `mod/build/libs/thaumcraft-1.21.1-1.1.0-sources.jar` | Архив исходников |

Задача `:mod:runClient` запускает клиент разработки, `addonSdk` собирает SDK дополнений. Обе команды принимают тот же параметр `aopUiJar`. Установка SDK, форматы данных и контракты API описаны в [руководстве разработчика дополнений](docs/addons/README.ru.md).

## Проверки и непрерывная интеграция

`build` компилирует проект и выполняет проверки API и отдельных правил. Игровые сценарии размещены в отдельных проверочных наборах исходников и исключены из игрового JAR. Успешная сборка и проверка в игре учитываются отдельно.

CI запускается при изменении исходников и сборочных файлов. Правки только документации сборку не запускают. Push в `main` сохраняет отдельный канал ночных сборок.

Для выпуска обычного GitHub Release откройте **Actions → Build and release → Run workflow** и включите **release**. Релиз получает тег `v<версия>`. Пустое поле **version** использует `mod_version` из `gradle.properties`; значение `major.minor.patch` переопределяет версию только для этого запуска. Выбранная версия применяется к метаданным JAR, именам файлов и тегу; исходные файлы workflow не изменяет. Суффиксы предварительных версий в режиме релиза отклоняются. Существующие теги релизов не перезаписываются. Push в `main` и ручной запуск с выключенным **release** обновляют единственный предварительный релиз `nightly`. Версия его JAR имеет вид `<mod_version>-nightly.<коммит исходников>`. Pull request только собирает артефакты без публикации. Локальный `act` ничего не публикует. Заметки обычного релиза содержат все коммиты после ближайшего предыдущего обычного релиза в выбранной истории, ссылки на коммиты и сравнение. Первый релиз включает всю историю. В nightly этот список не добавляется.

Отдельные CI и **Build mod suite** используют одинаковые сборочные команды и формат `aop-suite-manifest.json`. Отдельный workflow собирает или переиспользует свой компонент и необходимые зависимости, но публикует только свой компонент. Комплект может загрузить его JAR из Releases соответствующего репозитория при совпадении ревизии и содержимого исходников, версии, инструментов сборки, сборочных команд и контрольных сумм зависимостей. Кэши репозиториев независимы; обмен готовыми JAR между репозиториями выполняется через Releases. Nightly принимает подходящие релизные и nightly-артефакты, обычный релиз — только релизные, включая зависимости. Параметр `force_rebuild` отключает переиспользование готовых JAR и сохраняет Gradle-кэш.

**Actions → Build mod suite** собирает и проверяет **AOP: UI → TC4 и API → Thaumic Tinkerer → Forbidden Magic → Thaumic Energistics → Compact** в одном workflow. Проверенные JAR передаются следующему этапу; публикация каждого компонента в его репозитории начинается после успешной проверки всех шести этапов. С выключенным **release** обновляются `nightly`, с включённым — выпускаются обычные релизы. Шесть необязательных полей версии независимо используют `gradle.properties` соответствующего репозитория. Существующий обычный релиз переиспользуется только при совпадении приложенного манифеста комплекта; конфликтующие теги отклоняются до начала публикации.

Сначала проверяются точные записи кэша готовых JAR и манифесты опубликованных релизов. Совместимость определяется ревизиями и содержимым исходников, выбранными версиями, Java и платформой, сборочными командами и контрольными суммами JAR зависимостей. Nightly может использовать подходящие релизные и nightly-JAR; обычный релиз — только релизные. Отсутствующий, несовместимый или повреждённый артефакт пересобирается с использованием Gradle-кэша. Новые nightly комплекта получают суффикс исходного коммита, чтобы неизменившиеся JAR можно было использовать повторно. Прежние артефакты без манифеста пересобираются один раз. **force_rebuild** отключает переиспользование JAR, сохраняя Gradle-кэш. Каждая публикация включает `aop-suite-manifest.json` и контрольные суммы; полный комплект также сохраняется в артефактах Actions. Публикация шести репозиториев выполняется последовательно, без общей атомарной операции: при ошибке часть компонентов уже может быть опубликована, а workflow сообщит о сбое.

Для комплекта настройте в этом репозитории секрет `DEPENDENCY_TOKEN` с правом **Contents: Read and write** для всех шести репозиториев. Отдельной сборке достаточно права чтения её зависимостей. Запуск комплекта: `gh workflow run suite.yml --repo Salossov/AOP-Thaumcraft-4 --ref main -f release=false`.

Для локальной проверки отдельного workflow через `act` подготовьте исходники UI в `.dependencies/aopui`. Комплект дополнительно использует `.dependencies/tinkerer`, `.dependencies/forbidden`, `.dependencies/thaumicenergistics` и `.dependencies/compact`; команда `act workflow_dispatch -W .github/workflows/suite.yml` проверяет всю последовательность без публикации. Формат инвентаря экспортированных исходников описан в [сборочном скрипте](.github/scripts/suite.py). Постоянный каталог `SUITE_CACHE_DIR` и том с Gradle user home позволяют проверить повторное использование локального кэша. Локальные запуски пропускают API артефактов и кэша GitHub и публикацию; эти действия проверяются на GitHub.

| Переменная репозитория | Назначение |
| --- | --- |
| `AOPUI_REPOSITORY` | Исходники AOP: UI; `Salossov/AOP-UI` |
| `AOPUI_REF` | Ревизия AOP: UI; по умолчанию `main` |
| `TINKERER_REPOSITORY`, `TINKERER_REF` | Исходники дополнения для комплекта; `Salossov/AOPTC4-Thaumic-Tinkerer`, `main` |
| `FORBIDDEN_MAGIC_REPOSITORY`, `FORBIDDEN_MAGIC_REF` | Forbidden Magic source; defaults to `Salossov/AOPTC4-Forbidden-Magic`, `main` |
| `THAUMIC_ENERGISTICS_REPOSITORY`, `THAUMIC_ENERGISTICS_REF` | Thaumic Energistics source; defaults to `Salossov/AOPTC4-Thaumic-Energistics`, `main` |
| `COMPACT_REPOSITORY`, `COMPACT_REF` | Исходники интеграций для комплекта; `Salossov/AOPTC4-Compact`, `main` |

Сообщение об ошибке должно содержать версии компонентов, шаги воспроизведения, ожидаемое и фактическое поведение, а также соответствующий журнал или отчёт о сбое. Учётные данные и личные сведения необходимо удалить из вложений.

Compact и полная suite автоматически получают исходники Thaumic Energistics и собирают его после UI/ядра, до Compact. Переменные URL/SHA архива не нужны. Ревизия, содержимое исходников и хеш JAR ThE входят в ключ кеша Compact; ThE не встраивается в Compact. Пока репозиторий ThE закрыт, `DEPENDENCY_TOKEN` также нужен Contents read для него. Источник можно переопределить через `THAUMIC_ENERGISTICS_REPOSITORY` / `THAUMIC_ENERGISTICS_REF`. Для локального `act` нужны `.dependencies/thaumicenergistics` либо `SUITE_THE_ROOT`. Suite публикует все шесть компонентов, включая Forbidden Magic и Thaumic Energistics. Внешние зависимости FM закреплены URL/SHA в его `.github/ci-external.json`. Для локального act также нужны `.dependencies/forbidden` либо `SUITE_FM_ROOT`.
